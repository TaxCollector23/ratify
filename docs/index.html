Documentation

Ratify turns your repository's engineering standards into executable doctrine, and evaluates every pull request against that doctrine before human review begins.

How it works

1. Repository indexing

When Ratify is installed, it clones the repository, parses structure and symbols, builds a dependency graph, and mines merged PRs, review comments, and docs for precedent.

2. Doctrine inference

Recurring patterns in review feedback and repository history are turned into structured, scored doctrine rules — distinguishing hard rules from soft norms.

3. Pull request analysis

On every PR, deterministic policy checks run first. Only after context is assembled does Ratify call a model — to reason over evidence, not to invent it.

4. Evidence-backed findings

Every finding ships with severity, confidence, supporting evidence, and precedent — so reviewers evaluate Ratify's reasoning instead of taking a verdict on faith.

Installing the GitHub App

Ratify installs as a GitHub App scoped to the repositories you choose. It requests read access to code, pull requests, and checks, and write access to checks and PR comments only.

1. Go to github.com/apps/ratify (coming soon)
2. Select the organization and repositories to install on
3. Ratify begins indexing automatically

Local development (backend)

The backend is a pnpm monorepo. See the backend README in the repository for the full architecture, package layout, and setup instructions.

cp backend/.env.example backend/.env
docker compose -f backend/docker-compose.yml up --build
